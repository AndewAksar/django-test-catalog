# Django Test Catalog

## Запуск через Docker
1. Соберите и поднимите сервисы (PostgreSQL 13, Redis 5 и Django) командой:
   ```bash
   docker compose up --build
   ```
   В контейнере автоматически выполнятся миграции и запустится сервер разработки на `http://localhost:8000`.

2. При необходимости измените параметры окружения (пароль БД, хосты и т.д.) в `docker-compose.yml`. Все они пробрасываются в `settings/local.py` через переменные среды. При первом запуске `docker-compose` скопирует шаблон `settings/local.py.example` в `settings/local.py`, чтобы не хранить чувствительные данные в репозитории. Убедитесь, что файл называется точно `settings/local.py.example` (без лишних расширений), иначе контейнер выводит ошибку и завершает старт.

3. Для ручного выполнения команд (например, создание суперпользователя) используйте:
   ```bash
   docker compose run --rm web python manage.py createsuperuser
   ```

## Локальная настройка без Docker
Если вы запускаете проект без контейнеров, создайте файл `settings/local.py` (шаблон уже включён и использует переменные среды) и укажите параметры подключения к PostgreSQL/Redis, `DEBUG`, `ALLOWED_HOSTS` и т.п. Пример переменных приведён в `docker-compose.yml`.

## Разбор работы приложения

### Общая архитектура и ключевые модули
Проект представляет собой Django-приложение с модулем каталога (`catalog`) и REST API на базе Django REST Framework. В составе проекта подключены:
* Django Admin с темой Grappelli и файловым менеджером FileBrowser.
* REST API с токен- и сессионной аутентификацией, JSON-рендерингом и фильтрацией через `django-filter`.
* Redis как кэш и backend для очередей Django RQ (подключено в админке).

Точка входа для REST — префикс `/rest/` в корневых маршрутах, а админка доступна по `/admin/`. В `urls.py` зарегистрированы как admin-маршруты (включая Grappelli, FileBrowser и Django RQ), так и REST-маршруты каталога, плюс endpoint получения токена. Медиа и статические файлы раздаются Django при запуске в режиме разработки через `static()` и `staticfiles_urlpatterns()`.

### Конфигурация окружения
* Основные настройки собраны в `settings/` и включаются через `settings/__init__.py`.
* `settings/core.py` описывает базовые настройки Django (INSTALLED_APPS, MIDDLEWARE, DATABASES, STATIC/MEDIA и т.п.), а также устанавливает локаль и временную зону.
* `settings/rest_framework.py` задаёт дефолтные политики DRF: доступ к API по умолчанию только для аутентифицированных пользователей, JSON-ответы, пагинация и фильтры.
* `settings/cache.py` включает Redis для кэша и сессий, а `settings/rq.py` — очередь задач через Django RQ.
* `settings/local.py` должен содержать локальные параметры, которые переопределяют хосты, доступы и пароли. Шаблон `settings/local.py.example` показывает рекомендуемые переменные среды.

### Модель данных каталога
В приложении `catalog` реализованы три модели:
* **Product** — товар с полями `name`, `description`, `base_price`, `sort_order`. Используется сортировка по `sort_order` и названию.
* **ProductImage** — изображение товара: файл (`image`), подпись (`caption`), порядок сортировки (`sort_order`); связь `ForeignKey` на `Product` с `related_name='images'`.
* **ProductParameter** — параметр товара: имя (`name`), значение (`value`), цена (`price`), порядок сортировки (`sort_order`); связь `ForeignKey` на `Product` с `related_name='parameters'`.

Сортировки по умолчанию заданы в `Meta.ordering`, поэтому и админка, и API будут возвращать данные в предсказуемом порядке.

### Административная часть
В Django Admin для модели `Product` настроены:
* отображение списков с базовой ценой и порядком сортировки;
* поиск по названию, описанию, а также связанным параметрам и подписи изображения;
* inline-редактирование изображений и параметров через `TabularInline`.

За UI и дополнительную функциональность отвечают Grappelli и FileBrowser, которые подключены к админке через `urls.py` и соответствующие настройки в `settings/`.

### REST API каталога
Базовый префикс API: `/rest/`.

#### Аутентификация
DRF использует `SessionAuthentication` и `TokenAuthentication`. Для получения токена предусмотрен endpoint `/rest/token/`, который отдаёт токен по логину/паролю.

#### Эндпоинты каталога
Маршруты находятся в `catalog/urls.py` и подключаются под `/rest/`:
* `GET /rest/catalog/products/` — список товаров (упрощённые данные).
* `GET /rest/catalog/products/<id>/` — детальная информация по товару (описание + вложенные списки изображений и параметров).
* `GET /rest/catalog/parameters/` — агрегированные параметры для фильтрации: список имён параметров с уникальными значениями и количеством товаров.
* `GET /rest/catalog/products/<product_id>/image/` — список изображений товара.
* `GET /rest/catalog/products/<product_id>/parameter/` — список параметров товара.

Данные сериализуются через `catalog/serializers.py`. Для списка и детальной карточки используются разные сериализаторы (`ProductListSerializer` и `ProductDetailSerializer`), а изображения и параметры описаны отдельными сериализаторами.

### Фильтрация списка товаров
В `ProductListView` подключён `ProductFilter` (используется `django-filter`). Доступны фильтры:
* `param_name` — фильтрация по названию параметра (`parameters__name`), нечувствительно к регистру.
* `param_value` — фильтрация по значению параметра (`parameters__value`), нечувствительно к регистру.

Таким образом, список товаров можно получать с фильтрами по параметрам, а также использовать endpoint параметров для построения UI-фильтров.

### Хранение файлов и медиа
* Загруженные изображения товаров сохраняются в `media/products/`.
* FileBrowser использует директорию `uploads/` и набор разрешённых расширений (настройки в `settings/filebrowser.py`).
* `MEDIA_URL` и `STATIC_URL` сконфигурированы в `settings/core.py` и подключены в `urls.py`.

### Очереди и кэш
Redis используется как backend для:
* кэша приложения и хранения сессий (настройки в `settings/cache.py`);
* очередей задач через Django RQ (настройка `settings/rq.py`, UI доступен в админке `/admin/django-rq/`).
